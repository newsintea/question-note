# 学びノートを作る

それまでの会話で、ユーザーが何を疑問に思い、何がわかったのかを1ページにまとめる。
会話の記録ではなく、**あとで読み返したときに理解を思い出せるノート**にする。

## 手順

1. 会話を振り返って、次を整理する
   - きっかけになった疑問（音声入力の変換ミスや言い直しは直して、自然な文章にする）
   - 結局わかったこと（ノートの核）
   - 途中で出てきた深掘りや、最初の思い込みとの違い
   - まだ答えが出ていないこと（あれば）
2. 事実・数字・仕組みなど**根拠が大事な内容は、信頼できる情報源で確認する**（公的機関、公式ドキュメント、仕様書、論文、専門機関、メーカーの公式情報など）。会話中に答えた内容でも、確認できなければ直すか「未確認」と書く
3. `notes/<英小文字-ハイフン区切りのslug>.html` にノートを作る。HTMLの骨組み・クラス名は既存のノート（`notes/why-sky-is-blue.html`）に揃える
4. タグを1〜3個付ける
   - まず `index.html` の `data-tags` を見て、既存のタグを優先して使う。新しいタグは本当に必要なときだけ作る
   - タグは日本語の短い名詞（例: `科学` `健康` `お金` `歴史` `言葉` `料理` `IT` `ネットワーク`）
   - ノートページの `.tags` と、`index.html` の `data-tags` を必ず同じにする
5. `index.html` の `<ul class="note-list">` の**先頭**に `<li>` を追加する（既存の `<li>` と同じ形）
6. 新しいブランチでコミットし、push して、`main` 向けの Pull Request を作る（`gh pr create` は使えないので `gh api repos/{owner}/{repo}/pulls` を使う）
7. 最後に、PRのリンクとノートの要点を3行くらいで返す

## ノートの構成

上から順に、この形にする。

1. `<h1>` タイトル：わかったことが伝わる一文（例: 「空はなぜ青く、夕焼けはなぜ赤いのか」）
2. `.note-meta`：日付（`<time datetime="YYYY-MM-DD">`、JST）とタグ
3. `.question`：きっかけになった疑問
4. `.summary`（見出しは「ひとことで」）：**最初に端的なまとめ**。2〜4行の箇条書きで、これだけ読めば要点がわかるようにする
5. 本文（`<h2>` で区切る）：会話で深掘りした順ではなく、**理解しやすい順**に並べ直す
   - 最初の思い込みと実際が違った場合は、その違いを書く（学びとして価値が高い）
   - まだ答えが出ていないことがあれば、最後に「残った疑問」として書く
6. `.references`：参照した情報源のURL。**事実や根拠が大事な内容があるノートでは必須**。個人の考えの整理や感想が中心のノートなら省略してよい

## 書き方

- 専門用語は最初に出てきたところで短く説明する。詳しくない人が読んでもわかる文章にする
- 仕組みや流れ、比較は**インラインSVGで図解**する（`.figure` 内）
  - 幅は `viewBox="0 0 320 …"` を基本にして、スマホで文字が小さくならないようにする
  - 色はCSSのクラス `label` / `sub` / `box` / `fill-muted` / `stroke-mark` / `text-mark` などを使い、ダークモードでも読めるようにする。`stroke-blue` / `text-blue` は「青」そのものを表すときだけ
- 表は `.table-wrap > table`、補足は `.aside`、注意点は `.caution`、コードは `<pre><code>`
- 健康・お金・法律などの話題は、一般的な情報であることがわかる書き方にし、断定しすぎない
- 外部のJS・CSS・フォントは読み込まない。画像は `images/` に置く
- 会話中のユーザーの個人的な事情（仕事、住んでいる場所、人間関係など）は書かない
